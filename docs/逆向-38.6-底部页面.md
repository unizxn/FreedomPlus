# 38.6.0 直播页底部 UI 与 tab 行：静态逆向结论

反编译环境：jdax 1.5.6；APK 159.7MB（38.6.0 / 380600）。
全量 jadx 因会话超时被中断，改为按 dex 定点：
`classes8/14/16/29.dex`（约 14.5k 个类）反编译到 `C:/Users/A/Desktop/1/dy-dex-src`，覆盖了本次要看的全部目标类。

## 1. 底部渐变压暗层 `MultiSegmentMaskView`（id `oi`）

- 类：`com.ss.android.ugc.aweme.feed.mask.ui.MultiSegmentMaskView`
- 绘制：`onDraw(Canvas)` 里按自身 `measuredHeight` 画 `LinearGradient`，**高度完全由外部设置**，类内部不自算。
- 高度设置：`com.ss.android.ugc.aweme.feed.quick.presenter.FeedBottomMaskPresenter`
  - `LJJIJIIJIL(Integer)`：`height2 = container.getHeight() - inset(view 0x7f0a04e5)[1]`，再减去 `desc`(0x7f0a0165) 的高度，最后 `UtilsKt.updateHeight(mask, dp(height2))`（见源码 842~880 行）；
  - `LJJIJIL(boolean)` 是另一条按 dp 设高的分支（awemeType==3 图文时 +this.C）。
- 也就是说：**遮罩底边 = 某个容器的高度减去一个 bottom inset**。实测它恰好停在 2205（tab 行顶边），说明这个“容器高度 - inset”在 feed 里就是 tab 行以上的区域。

结论：遮罩不是“页面自绘”，而是 feed presenter 主动配置的一层；要让它消失，隐藏视图（alpha=0）或拦 `UtilsKt.updateHeight` 都可行，**不必按文本/坐标猜**。

## 2. 直播预览页容器 `LivePreviewFrameLayout`

`com.ss.android.ugc.aweme.feed.ui.LivePreviewFrameLayout` 只重写了 `setTranslationY`（加了一个 `a` 开关，`LIZIZ()` 之后才允许位移），没有任何 measure/layout/inset 逻辑。

⇒ 直播页的高度与底部 UI 位置**不归 feed 管**，来自直播 SDK 自己的布局。实测 `LivePlayerView` 高 2475，而页面高 2340、tab 行占 2205-2340：直播 SDK 把内容画到了 tab 行以下。

## 3. 「讲解中」那一行

- 全量资源里**搜不到**「讲解中」这个字符串（`resources/res` 与 `sources` 都没有），说明它是**服务端下发文案**。
- 这就是之前“按文案定位上移”命中率不稳的根本原因：不同直播间文案不同，甚至可能没有这一行。

## 4. 底部 tab 行 `MainBottomTabContainer`

`com.ss.android.ugc.aweme.homepage.ui.bottombar.MainBottomTabContainer`，实测 `0,2205-1080,2340`（135px）。
它不参与直播页的 measure；直播页只是“不知道自己只该画到 2205”。

## 结论与建议

1. **遮罩（灰带）**：可靠修法是把 `oi` 这个视图在沉浸模式下置为不可见——最好 hook `FeedBottomMaskPresenter` 设置高度之后，或直接在扫描时 `alpha=0`（视图实例每次页面重建都会变，需要每次扫描）。
2. **讲解中压 tab 行**：根因在直播 SDK，feed 侧无法通过布局约束修正；可选
   - a) 直播页把 tab 行恢复不透明（稳定，视觉上等于“盖住”）；
   - b) 由模块给直播页底部加内边距/位移（依赖 SDK 内部结构，稳定性差）。
3. 想解释“31.7.2 为什么不重叠”，需要 31.7.2 的 APK 做同层对比（`pm path` 拉取后同样看 `LivePlayerView` 高度与 `FeedBottomMaskPresenter` 的 inset 计算）。
